# PhosKinTime v0.6.0

This release corrects several scientific errors found in the November 2026 audit. **Results change**: fits made with
earlier versions cannot be reproduced with v0.6.0. See the [CHANGELOG.md](https://github.com/bibymaths/phoskintime/blob/main/CHANGELOG.md) and
[KNOWN_ISSUES.md](https://github.com/bibymaths/phoskintime/blob/main/KNOWN_ISSUES.md) for details.

## Interpreting results
- **Parameters at bounds are not estimates.** In the network fits used to validate this release (ABL2 subnetwork; distributive, sequential and
  combinatorial models), 9–10 of 21 parameters end at or within
  1 % of their data-derived bounds. Such a value marks where the bound stopped the fit; the true value may lie beyond
  it. Read only parameters away from their bounds as estimates ([KNOWN_ISSUES N22](https://github.com/bibymaths/phoskintime/blob/main/KNOWN_ISSUES.md); the bound rule is under review).
- **protwise fits are limited by the model structure.** With constant inputs, a protwise model relaxes to a fixed
  point within minutes, while the data change over hours; fits are often little better than a constant line, and
  slower solutions push rates to their bounds. Treat protwise parameters as descriptive, not as rate estimates, until a
  kinase-driven protwise model exists ([KNOWN_ISSUES P10](https://github.com/bibymaths/phoskintime/blob/main/KNOWN_ISSUES.md)). Check each gene's optimizer status in metadata.json:
  "not_converged" fits return the best iterate found, not a converged optimum.

## Results changed
- **Sequential model (N20):** a measured site is compared with its occupancy — the sum of all states in which it is
  phosphorylated. The sequential right-hand side now exists in the JAX fit (N1; it previously fell back to the
  distributive equations). Sites are phosphorylated in residue order (documented assumption).
- **Combinatorial model (N9):** protein degradation applies once per molecule (state decay = D + Σ site losses).
- **Solver (N5):** one ODE solver setting (rtol = atol = 1e-8) for fit, exports, steady state, sensitivity and
  posterior/profile rebuild; converged relative to data noise (1e-8 vs 1e-12: objective terms within 8e-9).
- **Fold-change scaling (N7):** data and model are both divided by their own value at the baseline time
  (scaling_method = "fc_start"); bad baselines are skipped and counted; scaled observations are saved with each run.
- **Kinase drive (N17):** a monotone cubic (PCHIP) through the measured kinase values, identical in fit, exports and
  SBML; after the last measured point it is held ("hold", default; stimulation is sustained in this dataset) or
  decays to baseline ("baseline").
- **protwise RNA timing (P1):** RNA predictions are read at the RNA observation times (15 min, not 16), for any grid.
- **protwise initial conditions (P4, initial-condition policy):** each species starts from its t = 0 measurement;
  otherwise from the model's own steady state under the t = 0 inputs (default) or an estimated value (opt-in);
  randmod starts from independent site occupancies that reproduce the t = 0 data.
- **protwise optimizer:** the best iterate is returned (not the last one) and each gene's status (converged /
  not_converged), iterations and gradient norm are recorded in metadata.json.

## Disabled
- **Posterior sampling (N6):** its likelihood was not a normalized likelihood; requesting it stops the run with an
  explanation. A proper likelihood is planned.

## Other changes
- metadata.json records the settings actually used (loss, solvers, bounds, scaling, drive, seeds, initial conditions);
  posterior/profile rebuilds use the run's own recorded settings.
- **SBML export with the PCHIP drive:** each kinase drive is written as an exact piecewise cubic (one cubic per
  interval between measured points, the same coefficients as the fit) plus the configured extrapolation after the
  last point. The SBML drive matches the fit's drive to ≤ 1e-12, and the exporter's own consistency check passes on
  the validation fit; the export is no longer blocked.
- The PINN/NeuralODE code moved to experimental/ and is not available in
  the workflows; profiles are labelled as training-objective differences (not likelihood profiles).
- Removed config keys (now errors): `loss` ≠ 0, `[networkmodel.bounds]`, `[ode.bootstrap]`, `normalize_model_output`.
- New config keys: `fc_baseline_near_zero`, `drive_extrapolation`, `drive_baseline_tau`, `[ode.fit] ic_policy`,
  `ic_estimate_bounds`. Inference keys moved to `[networkmodel]` (`profile_grid_size = 10`, the value in effect).
- Concurrent runs no longer share output or log folders; one --seed for the sensitivity analyses; NaN targets are
  masked and counted; a failing gene no longer stops a protwise run.

## Known limitations (pending)
- networkmodel initial conditions use the 4-min RNA value at t = 0 (a steady-state rule worsens fits by ≈ 6 %;
  an estimated initial condition is still to be tested; [KNOWN_ISSUES N18](https://github.com/bibymaths/phoskintime/blob/main/KNOWN_ISSUES.md)).
- Morris sensitivity (off by default) keeps the fitted initial state while perturbing parameters ([KNOWN_ISSUES P11](https://github.com/bibymaths/phoskintime/blob/main/KNOWN_ISSUES.md)).
- protwise has no time-varying input: fits relax within minutes (a kinase-driven protwise model is proposed).
- Posterior sampling disabled until a proper likelihood exists.
